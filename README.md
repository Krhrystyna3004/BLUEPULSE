# BluePulse — блог новин і спільнот

Багатосторінковий вебзастосунок українською: стрічка новин, теми, пошук, групи, реєстрація/вхід, профіль, персональна стрічка та базовий RSS-імпорт.

## Запуск локально

1. Встановіть Python 3.10+.
2. Створіть і активуйте віртуальне середовище:
   ```bash
   python -m venv .venv
   # Windows: .venv\\Scripts\\activate
   # macOS/Linux: source .venv/bin/activate
   ```
3. Встановіть залежності: `pip install -r requirements.txt`
4. Скопіюйте `.env.example` у `.env` та задайте унікальний `SECRET_KEY`. Для локального тесту змінні можна не завантажувати — застосунок має безпечніші за замовчуванням налаштування, але секрет обов'язково змініть перед публікацією.
5. Запустіть: `python app.py`
6. Відкрийте http://127.0.0.1:5000

SQLite-база `bluepulse.db` створюється автоматично. Перший запуск додає демонстраційні теми й матеріали.

## Щоденне наповнення RSS

RSS-імпорт вимкнений за замовчуванням. Це навмисно: сам факт наявності RSS не означає, що дозволено повторно публікувати його вміст. Перед додаванням джерела перевірте ліцензію, умови використання та правила атрибуції. Вкажіть точні URL у `RSS_FEEDS`, а домени — у `ALLOWED_FEED_HOSTS`, потім встановіть `ENABLE_SCHEDULER=1`. О 07:00 за `APP_TIMEZONE` застосунок перевірятиме ці стрічки.

Імпортер зберігає заголовок, короткий опис зі стрічки та посилання на оригінал; він **не копіює повні статті**. Використовуйте лише джерела з явним дозволом на таке використання (наприклад, матеріали з ліцензією CC0/CC BY із дотриманням її умов або офіційні пресрелізи, умови яких дозволяють передрук). Якщо умови джерела неясні — не додавайте його. Не можна гарантувати автоматично, що будь-яка новина «не порушує закон»: потрібна перевірка джерел і редакційний контроль.

### ШІ-редагування (опційне розширення)
У проєкті передбачено безпечну точку інтеграції: перед публікацією можна додати сервіс на базі API-моделі, який класифікує тему, формує короткий переказ власними словами та позначає сумнівні матеріали для ручної перевірки. Не передавайте моделі повний текст, якщо ліцензія цього не дозволяє. Не публікуйте автоматично неперевірені твердження. Для production-режиму додайте чергу `pending_review`, журнал джерел, модераторське схвалення та обробку помилок. У поточному MVP ШІ ще не підключений: автоматизація щодня перевіряє лише внесені адміністратором RSS-джерела. Для реального ШІ-модуля потрібні API-ключ, окрема перевірка контенту та модераторське схвалення; це навмисно не імітується фіктивною кнопкою.

## Перед публікацією в інтернеті
- Задайте довгий випадковий `SECRET_KEY`; використовуйте HTTPS.
- Перейдіть на PostgreSQL через `DATABASE_URL` для багатокористувацького production.
- Додайте CSRF-захист, rate limiting, підтвердження email, відновлення пароля та політику конфіденційності.
- Для кількох Gunicorn workers винесіть планувальник в окремий worker/cron, щоб не запускати однакові задачі кілька разів.
- Перевірте права на кожне джерело та налаштуйте процес скарг/видалення.

## Структура
- `app.py` — Flask backend, моделі SQLite, маршрути, RSS-планувальник.
- `templates/` — сторінки сайту.
- `static/style.css` — адаптивний синьо-блакитний дизайн.
